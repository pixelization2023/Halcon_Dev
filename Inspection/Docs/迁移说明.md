# 窗体（WinForms）→ camerateset_AI（WPF + Halcon）迁移说明

本次迁移把 `E:\黑鲸鱼的工作区\窗体` 这个 .NET Framework 4.7.2 WinForms 视觉检测上位机的业务逻辑，
重构进 `camerateset_AI` 解决方案，UI 全部改为 **WPF（Prism + MVVM）**，视觉引擎由
**VisionMaster（VM）替换为 Halcon（HDevelop 引擎）**。

新增工程：`Inspection\Inspection.csproj`（作为 Prism 模块被 `MultiCameraSystem` 加载）。

## 2. Halcon 过程约定（替代 VisionMaster 流程）

现场需要把原来的 VM 流程改写成 HDevelop 的**本地函数（procedure）**，保存成 `.hdev` 文件，
放到产品目录：`{程序目录}\Product\{产品名}\{方案名}.hdev`。

命名约定与原来的 VM 输出完全一致，便于直接搬运：

| 用途 | 参数名 | 备注 |
| --- | --- | --- |
| 输入图像 | `Image`（可配置） | 对应原 `ImageSourceModuleTool.SetImageData` |
| 检测结果 | `out{0}`、`out{1}` … | 索引 = 该图片内 PCS 序号 × 检测项目数 + 检测项序号 |
| NG 框 | `box{0}`、`box{1}` … | 区域或 XLD 均可，自动用 `smallest_rectangle1(_xld)` 提取 |
| PCS 结果图 | `image{0}`、`image{1}` … | 可选；不声明则不输出图像 |
| 扫码结果 | `code`（可配置） | 扫码流程的过程名需包含「扫码」 |
| 图片序号 | `ImageIndex` | 运行前自动注入（1 开始） |

结果字符串判定规则与原项目一致：**空串按 NG 处理，仅 `OK`（忽略大小写）视为 OK**。

参考模板见 `Docs/HalconProcedureTemplate.hdev`。

## 3. 配置格式变更

- 原：`{产品目录}\{产品名}.asol`（`BinaryFormatter` 二进制序列化）。
- 现：`{产品目录}\{产品名}.json`（UTF-8 JSON，`System.Text.Json`）。
- 原因：`BinaryFormatter` 在 .NET 9 已被移除（且存在反序列化安全风险）。
- 历史 `.asol` 文件无法自动读取，需要在现场重新配置一次（配置文件本身很小）。
- 分组键沿用原来的中文名：`通用设置 / 存图设置 / MES设置 / 通讯设置 / 数据库设置`；
  原 `VM设置` 改名为 `视觉设置`（读取时做兼容映射）。

## 4. 有意为之的行为修正

迁移过程中修复了原实现里的若干缺陷，现场需知悉：

1. `HalconEngine` 原来用 `HDevProcedureCall` 去执行 `HDevProgram`，
   主程序（`.hdvp`）路径实际不可用；现已按「主程序 / 外部过程」两种模式分别实现。
2. 原项目在 OK 分支误用了 `NGImageSavePath` 保存 OK 图，现已按判定选择正确根目录。
3. `StatusMonitorService` 数据库连通性检测不再每个心跳周期都新建连接。
4. `Workspace` 主窗口的「工作台」与「系统设置」原来共用同一个选中标志，现已拆分。
5. 图像存盘由 `Halcon write_image` 直写，省去 Halcon → Bitmap → GDI+ 编码的一次转换。
6. MES 调用由同步阻塞改为 async + CancellationToken，并统一了超时（15s）。

## 6. 编译

```powershell
dotnet build HaiKangMVS.sln -m:1 -nodeReuse:false /p:UseSharedCompilation=false
```

> 说明：该沙箱环境下 MSBuild 的 out-of-proc 节点与 Roslyn 编译服务器会被拒绝启动，
> 因此上面的参数是必需的；在普通开发机上直接 `dotnet build HaiKangMVS.sln` 即可。
